# RDP combiner experiments

**Outcome: neither production optimization is retained.** Both preserve the
tested arithmetic and complete game states, but neither demonstrates a
consistent speed improvement in two complementary batches. The renderer source
is restored to `70e5e64`, including its already-validated direct hidden-bit
storage. Selector tests and the benchmark's reverse-order option are retained.
No new renderer speedup is claimed.

Follow-up to `70e5e64` and the MK64 race profile. In that profile, the combiner
and its surviving lambda accounted for about 10.36% of exclusive samples. This
experiment targets repeated input-source dispatch without changing equations,
rounding, chroma-key handling or the per-pixel noise sequence.

## Experiment 1: reference-table dispatch (rejected)

The first candidate built an eight-entry table per cycle with references to COMBINED,
TEXEL0, TEXEL1, primitive, shade, environment, ONE and ZERO. Ordinary selections
use that table instead of repeatedly switching on the source for each channel.
RGB A/B/C special selectors still take their existing paths. All calls to the
ordinary input accessor are bounded to 0..7 by their field masks or special-slot
guards. References remain valid until the current cycle returns. No decoded
state cache or serialized fields are added, and noise still advances once per
pixel even when neither cycle reads NOISE.

Two new selector tests provide 248 assertions covering every RGB A/B/C selector,
RGB/alpha D inputs, alpha A/B/C inputs, both cycle modes, COMBINED routing,
next-pixel TEXEL1, special key/LOD/convert inputs and unused-noise advancement.
All seven Debug suites pass; each N64 RSP/RDP combination passes **199 cases /
62736 assertions**. The production change is confined to the ordinary input
accessor; existing arithmetic, saturation, key, LOD, noise and blender tests
remain in the suite.

## Whole-game method

MK64 USA, Release/LTCG, interpreter, synchronous RDP, AVX2 OFF, fields
1500–1900 (400 timed VI fields). The first 1500 fields warm each cold process
outside the timed window. There is no sampling, build or other emulator workload
concurrent with timing. The baseline runner/PDB are preserved from `70e5e64`.

The first batch uses baseline/candidate, candidate/baseline, baseline/candidate
order. Because it is mixed and the baseline drifts, a second complementary
batch uses the new `benchmark-race.ps1 -Reverse` option with a separate output
directory. The tool still checks the exact image and complete-state hashes
after every process. Timings from the earlier hidden-bit optimization are not
used as this experiment's baseline.

| 2 | 16.032 / 15.984 | 15.492 / 15.453 | 3.32% |

The first batch alone was insufficient to establish a consistent improvement.
The complementary batch produced:

| Batch 2 pair | Baseline wall / CPU (s) | Table wall / CPU (s) | CPU reduction |

| 1 | 15.845 / 15.844 | 15.646 / 15.641 | 1.28% |

Only 4/6 pairs improve CPU, with a median paired reduction of **0.94%**. This

## Experiment 2: zero-product equations

When `(A - B) * C` is provably zero, the result of the combiner equation is D.
The second candidate uses this property instead of introducing an input table:

- RGB multiplier selectors 16..31 select zero.
- Matching RGB A/B selectors 0..5 refer to the same ordinary input. Reserved
  A/B selectors 8..15 both read zero, even when their codes differ.
- RGB slots 6 and 7 are excluded from the equality rule: their meanings differ
  between A and B (ONE/NOISE versus KEY CENTER/K4).
- Alpha multiplier selector 7 reads zero; equal alpha A/B selectors have the
  same meanings for all eight codes and therefore also cancel.

These cases read D directly and still apply the existing nine-bit saturation.
The final unclamped RGB remains available to chroma key. Other equations retain
the original path. Noise is still generated unconditionally once per pixel,
independently of either cycle using the noise value. No state/cache fields or
save-state versions change.

A third test covers nonzero multipliers with equal operands, reserved zero
operands, both cycles and unchanged noise progression. All seven Debug suites
pass, with **200 cases / 62762 assertions** per N64 combination. Release runner
and frontend build successfully. The new comparison uses `70e5e64` directly as
its baseline, not the rejected table candidate. Artifacts are under
`build/combine-zero/`.

| Zero-product batch 1 pair | Baseline wall / CPU (s) | Candidate wall / CPU (s) | CPU reduction |
| --- | --- | --- | ---: |
| 1 | 16.280 / 16.281 | 15.601 / 15.594 | 4.22% |
| 2 | 16.718 / 16.531 | 15.148 / 15.109 | 8.60% |
| 3 | 15.560 / 15.359 | 16.634 / 16.484 | -7.32% |

This batch is also mixed, so it is followed by a complementary reverse-order
batch before making a retention decision. All game states/images remain exact.

| Zero-product batch 2 pair | Baseline wall / CPU (s) | Candidate wall / CPU (s) | CPU reduction |
| --- | --- | --- | ---: |
| 1 | 15.601 / 15.578 | 15.490 / 15.438 | 0.90% |
| 2 | 15.006 / 15.000 | 15.399 / 15.328 | -2.19% |
| 3 | 15.407 / 15.406 | 15.283 / 15.281 | 0.81% |

CPU improves in **4/6 pairs**, with a median paired reduction of **0.86%** and
regressions of 7.32% and 2.19%. The first batch's 4.22% median did not reproduce
in the complementary batch. The shortcut was removed. Its source/patch and
matching executable/PDB remain in ignored `build/combine-zero/` for local audit.

Across both experiments, **all 24 complete game states and images match** the
reference hashes. Correctness alone does not establish a performance benefit.
Cold-process variation in these batches is larger than either aggregate effect;
do not present a favorable single pair or first-batch median as an improvement.

## Next bounded experiment

The unchanged race profile still points at the combiner, pixel output and
texture sampling. A different hypothesis is to decode uniform selectors and
colors when RDP state commands change them, instead of decoding them per pixel.
That is not implemented here: it requires explicit tests for immediate state
updates, reset and saved-state restoration before any following draw. The
current selector tests provide a conformance baseline for that work. Reuse the
same exact game-state checks and complementary process orders.

## Final restored-build verification

After restoring the renderer source to `70e5e64`, Debug was rebuilt and all
seven suites passed again, including **200 cases / 62762 assertions** in each
N64 RSP/RDP combination. Release runner and frontend were rebuilt sequentially.
The final runner's complete state at 120 fields matches the original scalar
reference. Logs are in `build/combine-zero/restored-tests.log` and
`build-restored-{debug,release}.log` in the same directory.

The final changes contain tests, documentation and `benchmark-race.ps1 -Reverse`;
there is no retained change under `src/core/n64/`. The historical systemtest
baseline is the already-verified 2984/3721 of `70e5e64`; it was not rerun for
these test/tool-only final changes, and no new systemtest result is claimed.
