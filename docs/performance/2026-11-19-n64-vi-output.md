# N64: cost and accuracy of the VI output filters (2026-11-21)

Branch `n64/vi-output`, Release, i7-4790. MK64 race, fields 1500-1900 (400 fields):

```
ezy_n64_runner.exe "E:/Rom nintendo/Mario Kart 64 (USA).z64" --benchmark build/vo/bench.bmp 1900 \
  --time-from 1500 --audio-hle --rdp-threaded --gfx-hle --cpu-jit [--vi-output]
```

With `--vi-output` the runner drains the threaded RDP once per field (untimed) and then times
`Vi::output()` once per field. ezyemu already drains the RDP per drawn frame (`image()` did too),
so only the `output()` time is new cost for the frontend.

## Cost of `Vi::output()` (640x480 per call)

| version | mean ms | max ms |
|---|---|---|
| first implementation (15f9d44) | 11.1-11.4 | 15.8-18.0 |
| row cache: each framebuffer row decoded once, filters inlined (WIP 50d763a) | 4.96 | 8.3-11.5 |
| + dither filter four pixels at a time (SSE2), divot only where coverage is partial | 3.31 | 4.8 |
| + vertical lerp once per framebuffer column, gamma mode as a template, integer gamma | 2.99-3.01 | 3.9-6.5 |
| + screen pixels four at a time (SSE2: lerp, gamma as 2 * isqrt with `sqrtps`, gamma dither) | 2.40 | 3.4 |
| + `output(rdram, hidden, Image&)` reusing the image buffer (ezyemu and the runner) | 1.98 | 2.6-5.1 |
| + 16-bit framebuffer rows decoded eight pixels at a time (SSE2, hidden bits read in a row) | **1.69-1.73** | 2.2-2.5 |

Split of the ~3 ms step (temporary timers, removed): ~0.3 ms allocating and clearing the
640x480 image (page faults of a new 1.2 MB buffer each frame), ~0.85 ms decoding and filtering
rows, ~1.8 ms emitting the screen pixels, of which ~1 ms was gamma + gamma dither (MK64 enables
both). Computing the noise in a separate loop first was slower (1.95 ms) and was dropped.
`sqrtps` is exact here: for integers below 2^24 the rounded square root never crosses an integer,
so `2 * (int)sqrt(i)` equals the table `kGammaTable` the scalar path still uses.

The 2 ms target of the plan is met on the emulation thread; no worker thread is needed.

Fields/s in the runner (two interleaved pairs): 59.58 / 61.15 without, 40.28 / 40.13 with
`--vi-output`; the gap is mostly the per-field RDP drain that only the runner adds (ezyemu
already drained the RDP for every drawn frame before this change).

## Exactness

- The optimisations are bit-identical: 24 MK64 images (fields 1500-1960) and 13 Spider-Man images
  (600-1200) from `--series ... --vi-output` match the WIP version byte for byte, and the unit test
  "VI output pixels stay identical across modes and geometries" (hashes of the scalar version
  15f9d44 over both pixel types, AA modes 0-3, divot, dither filter, every gamma combination,
  interlace, PAL and odd scales; now reusing one Image across all cases) still passes. Breaking
  the SIMD blue decode or a gamma-dither lane makes it fail.
- `--dump-state 1900 --audio-hle --rdp-threaded --cpu-jit`: SHA-1 4a4c0711b75a574a8f50bb2b49934bb6a494d518,
  the same as before Task 4 (the output does not touch the machine state).
- `ctest --preset debug` 11/11; Release `-R "peterlemon|systemtest"` 183/183.

## Against ares v148

Mean absolute grayscale difference at 640x480 (ares window cropped 752x570 at (8,2)):

| field | ares capture | raw framebuffer | VI output |
|---|---|---|---|
| 1780 | f_066 | 13.64 | 10.37 |
| 1786 | f_067 | 14.02 | 10.67 |
| 1792 | f_068 | 14.22 | 10.75 |
| 1798 | f_069 | 17.12 | 15.45 |
| 1858 | f_080 | 15.22 | 10.82 |
| 1864 | f_081 | 12.70 | 9.46 |

The VI output is closer to ares in all six pairs: edges are smoothed by the antialias, the 5-bit
dither on the road is filtered away, and the window leaves the black border on the last rows and
right column like the hardware. Side-by-side images (raw | VI output | ares) are in
`build/vis/vo_cmp_1780.png`, `vo_cmp_1798.png` and `vo_cmp_1864.png` (not in the repo).

## Last line of the image

The row of random colours at the bottom of MK64 is only in the raw framebuffer (`--vi-raw`,
`Vi::image()`), which shows the nominal 240 lines: the game draws fewer. The VI output follows
V_VIDEO and leaves those lines black, as ares does.
