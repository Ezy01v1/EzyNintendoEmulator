## Verdict

Criterion (median >= +10 % with >= 4/5 pairs in favour, graphics-HLE race): **met** (+12.8 %,
5/5). Clear gain; the project goes on to Phase 4.

Full NTSC speed: **yes**. With the graphics HLE the JIT race runs at 62.8-63.3 fields/s, above
60 (the interpreter's 55.7 is below). With LLE graphics it also reaches 62-64 fields/s.
Caveat: the gain is measured over the race only; the first seconds (compilation) are slower,
and the JIT runs ~6 s of compilation in a 1900-field run.

## Profile of the JIT race (`--profile build/jit-profile.csv`, graphics HLE)

One profiled run: 63.3 fields/s, 3183 main-thread samples, 0 capture errors (profiled timings
are not a result). Main-thread share:

| Group | Share |
|---|---|
| asmjit (compiling blocks; all `asmjit::*` frames) | **47.1 %** |
| ... of which register allocation (`build_liveness` 6.3, `alloc_instruction` 5.3, `bin_pack` 5.0, `RACFGBuilder` 3.3 + 3.0, ...) | ~30 % |
| ... of which emission (`x86::Assembler::_emit` 3.6, `BaseBuilder::_emit` 2.3, ...) | ~10 % |
| RSP native code | 7.6 % |
| `Vr4300Jit::execute` (the block dispatch) | 5.7 % |
| `Vr4300Jit::run` | 2.5 % |
| FP environment and libm (`fesetround` 2.5, `fdclass` 1.6, `fegetenv` 1.3, `truncf` 1.0, ...) | 8.6 % |
| `Vr4300::execute_cop1` + lambdas (FPU helpers) | ~3.5 % |
| `Vr4300::execute` (instructions left to the interpreter) | 1.6 % |
| memmove / memset / heap | ~4.2 % |
| `ZwYieldExecution` (waiting) | 0.9 % |

The interpreter's ~86 % of the main thread (cpu-profile doc) is gone: the native code itself
does not appear as a function (it runs from the JIT heap, unnamed), so its share is the
remainder. Compilation is still running during the race (blocks are first seen as MK64 loads
code and enters new areas), which is why asmjit is the largest line.

## What Phase 4 should attack first

1. **Compile cost** (47 % of the main thread in the profile, ~6 s of a 1900-field run). The
   asmjit Compiler's register allocator dominates; emitting through the Assembler with the fixed
   register assignment the blocks already use, or a cheaper pass, plus a persistent/reused code
   cache across runs, would cut most of it. This is the largest and most certain win.
2. **Native FPU**: `fesetround`, `fegetenv`, `fdclass`, `truncf` and the COP1 helpers together
   are ~12 % of the main thread. Inline SSE for add/sub/mul/div/cvt with the rounding mode
   hoisted per block (or only switched when the guest changes it) removes the libm and
   FP-environment calls.
3. **Block linking in native code** and **fewer exits**: 1.18 M exits before the block end and
   1.38 M out-of-block transitions each go through `Vr4300Jit::run`/`execute` (8.2 % together).
   Direct jumps between compiled blocks would remove them.
4. **Register cache across instructions** and smaller per-exit write-back stubs (code size also
   feeds the compile cost in item 1).
5. The 29.8 M "in place" instructions still go through helpers: check which opcodes dominate
   and move the hottest ones to native code.

## Caveats

- Single ROM (MK64), single machine, one profiled run.
- Pairs are interleaved in one session; absolute numbers drift between sessions (earlier
  documents measured the interpreter at 51-54 fields/s with graphics HLE, today 55-56).
- The LLE-graphics JIT result (62-64 fields/s) lands almost at the same level as the
  graphics-HLE one; the RDP threads, not the CPU, probably limit both now.
- Correctness of the JIT is covered by the earlier tasks' tests, not by this document.
