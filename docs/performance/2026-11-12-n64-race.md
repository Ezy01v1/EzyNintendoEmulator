# MK64 race profiling and direct RDP hidden bits

## Measurement window and baseline

This work follows `224eb73` on `codex/n64-rsp-jit`. The VMADN AVX2 option remains
OFF. The interpreter and synchronous RDP remain the runtime defaults.

The runner now has `--benchmark <image.bmp> <end> --time-from <first>` and optional
`--dump-final-state <state.bin>`. It runs the initial fields without timing, then
measures only the requested window, including the final RDP drain. Output,
screenshots, save-state serialization and profile resolution are excluded.
`benchmark-race.ps1` compares adjacent alternating processes and fails on any
image or complete-state mismatch. Commands and limits are documented in
`tools/n64_runner/README.md`.

MK64 USA, fields 1500–1900 (400 VI fields), Release/LTCG, synchronous RDP, this
PC only. Every process boots independently and warms its own translations during

## Statistical profile, collected separately

The optional Windows x64 sampler captures the main thread's RIP, resumes it
before allocating or resolving symbols, and resolves the matching PDB after the
window. It restores its timer-resolution request when stopped. Sampling is
diagnostic: none of its timings enter the performance comparisons.

| Exclusive sample group | Interpreter (9456 samples) | JIT (9700 samples) |
| --- | ---: | ---: |
| Named RDP functions | 31.67% | 31.51% |
| Named RSP functions plus generated code | 25.70% | 26.36% |
| VR4300/COP0/COP1/TLB | 14.82% | 15.07% |
| Map/tree library functions | 6.70% | 6.40% |
| `RtlAllocateHeap` | 2.12% | 2.01% |

Both captures have zero capture errors. LTO inlining and identical-function
folding mean these are approximate exclusive groups, not inclusive call-stack
costs; library template aliases can name a different instantiation sharing the
same machine code. Map/tree and allocator rows are not automatically charged to
RDP. Nevertheless the RDP's hidden-DZ map is the only `std::map` in the N64 core,
and its `operator[]` alone accounts for 3.68% / 3.49% of samples. It performs a
lookup and potentially an allocation on each depth write. This is a concrete
candidate to test before more JIT architecture changes.

Profiled and unprofiled states/images agree. Raw profiles, images, states and
matching baseline executable/PDB are in `build/race-baseline/`.

## Candidate: direct hidden-bit lookup

`RdpHiddenBits` replaces the sparse tree with a heap-allocated 4 MiB array: one
byte for the two hidden DZ bits of each halfword in 8 MiB RDRAM. Pixel reads and
writes use direct indexed access, with no tree lookup or per-entry allocation.
The nonzero count is maintained for serialization, and fill ranges clear exactly
the same halfwords as before. This trades fixed storage for faster access.

The v11 sparse state layout is unchanged: nonzero entries are emitted in sorted
halfword order. Older versions still clear the hidden bits. Malformed input
counts, invalid bits, out-of-RDRAM indices and truncated entries are rejected
before out-of-bounds access or unbounded iteration. Loading retains the previous
duplicate/zero-entry semantics.

Initial validation: all seven Debug suites pass. Each of the four N64
combinations passes **197 cases / 62488 assertions**. New tests compare random
writes/range clears with a `std::map` oracle, verify byte-identical sparse
serialization and loading, exercise the last halfword and clipped ranges, and
reject malformed states. Release runner and frontend build successfully; the
120-field complete game state matches the original map-backed reference.

## Paired candidate measurements

The preserved baseline runner and the candidate both contain the same benchmark
and sampling mechanism; sampling is disabled in these measurements. Three cold
process pairs use baseline/candidate, candidate/baseline, baseline/candidate
order, with the interpreter and synchronous RDP. The same 1500-field warm-up and
400-field race window are used in every process.

| Pair | Sparse map wall / CPU (s) | Direct storage wall / CPU (s) | CPU reduction |
| --- | --- | --- | ---: |
| 1 | 17.614 / 17.625 | 14.938 / 14.938 | 15.25% |
| 2 | 17.458 / 17.453 | 15.088 / 15.078 | 13.61% |
| 3 | 17.354 / 17.344 | 15.080 / 15.078 | 13.06% |

Median paired CPU reduction: **13.61%**, with improvement in all three pairs.
Wall medians are **17.458 / 15.080 s**, or **22.91 / 26.53 fields/s** (about
15.77% higher throughput). CPU medians are **17.453125 / 15.078125 s**.
All six complete states and images match the original race reference exactly.
Raw data and per-process artifacts: `build/race-hidden/results.json`.

The baseline in this second batch is faster than the earlier backend-comparison
batch. Use the adjacent pairs above to judge the change; do not inflate the
gain by comparing the candidate with the earlier 21.84 fields/s baseline.
This is evidence for this race window on this PC, not all games or 60 fields/s.

## Profile after the change

A separate interpreter/synchronous-RDP capture of the same window has 7788
samples, zero capture errors and zero unresolved samples. Its complete state and
image match the reference. Map/tree and `RtlAllocateHeap` samples drop to **zero**.
This supports removal of the specific lookup/allocation cost, independently of
the unprofiled timing comparison.

Named RDP functions now account for 35.70%, named RSP for 29.35%, and
VR4300/COP0/COP1/TLB for 16.49%. These are shares of the remaining samples, not an
increase in absolute RDP time. The RDP combiner plus its surviving lambda alias
accounts for about 10.36%, opaque-pixel output plus its lambda for 8.23%, and
texture sampling/read helpers for about 5.62%. These are candidates for the next
bounded experiment; no further speedup is claimed here.

Artifacts: `build/race-hidden/profile-candidate.{csv,log,bmp,bin}`. Profiled
timings are excluded from the paired performance result.

## Final verification

- All seven Debug suites pass, with 197 cases / 62488 assertions for each N64
  RSP/RDP combination. No core changes were made after this test run.
- All twelve unprofiled race images and full states across the two benchmark
  batches, and all three race profiles, have the same reference hashes above.
- Complete save/load continuation after **1900+120 fields** passes when switching
  from interpreter/synchronous RDP to JIT/threaded RDP, comparing final states
  and images. Log: `build/race-hidden/state-continuation.log`.
- The historical local n64-systemtest 2.1.0 base ROM finishes with JIT and
  synchronous RDP, AVX2 OFF: **737 failures out of 3721**, retaining the
  **2984/3721** passing baseline. The runner exits 1 for the known failures;
  validation checks the summary instead of calling this an all-passing suite.
  Log: `build/race-hidden/systemtest.log`.
- Release runner and frontend are rebuilt. The benchmark rejects invalid or
  empty timing windows; a short profiled run preserves the original complete
  game state. Diagnostic profiling and benchmark artifact output stay in the
  headless tool; no frontend UI behavior changes.

The direct storage is retained. JIT, threaded RDP and AVX2 remain experimental;
their defaults are unchanged, and this work does not merge them into main.
