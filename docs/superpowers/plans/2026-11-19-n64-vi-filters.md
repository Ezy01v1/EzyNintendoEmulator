# Salida del VI con sus filtros — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** que ezyemu muestre la salida del VI como la consola (antialias por cobertura, filtro de
tramado, divot, reescalado interpolado, gamma, ventana visible), sin cambiar el framebuffer
crudo que usan las pruebas.

**Architecture:** el RDP guarda la cobertura completa de 16 bits (bits ocultos de RDRAM); un
módulo nuevo `vi_filter` implementa cada etapa como funciones puras probadas por separado;
`Vi::output()` las encadena sobre la ventana visible y produce 640×480 (NTSC) o 640×576
(PAL); el frontend la muestra por defecto y el runner la guarda con `--vi-output`.

**Tech Stack:** C++20, MSVC 2022, CMake presets, doctest.

**Spec:** `docs/superpowers/specs/2026-11-19-n64-vi-filters-design.md` (aprobado 2026-11-19).

## Review Focus

1. **Juego que cambia de modo de video (16↔32 bits, tamaño de ventana, entrelazado) a mitad de partida**: la salida se adapta en el siguiente cuadro, sin restos ni lectura fuera de RDRAM. Prueba en la Tarea 3.
2. **Framebuffer en el borde de RDRAM o `VI_ORIGIN` inválido**: la salida no lee fuera de los 8 MB (píxeles fuera cuentan como negros con cobertura completa). Prueba en la Tarea 3.
3. **VI apagado (tipo 0/1) o ventana vacía**: salida negra del tamaño completo, sin cuelgues. Prueba en la Tarea 3.
4. **Cargar un estado guardado antes de este cambio** (bits ocultos de color en 0): la imagen se ve con cobertura parcial hasta que el juego redibuje; no debe fallar. Prueba en la Tarea 1 (cargar un estado sin bits ocultos de color y dibujar un cuadro).
5. **RDP en hilos**: la salida no muestra un cuadro a medio dibujar ni bits ocultos a medias. Prueba en la Tarea 3 (con `--rdp-threaded` en la suite).

Comportamiento del hardware a implementar:
- Color RGBA5551: cobertura almacenada `c` (0..7): bit 0 del halfword = `c >> 2`, bits ocultos del halfword = `c & 3`.
- Lectura de cobertura de memoria en 16 bits: `((halfword & 1) << 2) | hidden`.
- Relleno (fill) en 16 bits: los bits ocultos de cada halfword escrito toman `(halfword & 1) ? 3 : 0` (hoy se borran; con `0xFFFC` de los rellenos de Z sigue dando 0).
- RGBA8888 no cambia (la cobertura vive en los bits 7:5 del byte de alfa).

### Task 2: Etapas del filtro como funciones puras

**Files:**

**Interfaces:**
- Consumes: `RdpHiddenBits` (Tarea 1).
- Produces (namespace `ezy::n64::vi`):

```cpp
struct Color { std::uint8_t r = 0, g = 0, b = 0; std::uint8_t coverage = 7; };
struct Framebuffer {                       // a view of the image VI_ORIGIN points at
    std::span<const std::uint8_t> rdram;
    const RdpHiddenBits* hidden = nullptr; // nullptr: hidden bits read as 0
    std::uint32_t origin = 0, width = 0;   // VI_ORIGIN & 0xFFFFFF, VI_WIDTH & 0xFFF (pixels)
    bool rgba32 = false;
    bool use_coverage = true;              // AA_MODE 0 or 1; otherwise coverage reads as 7
};
// Pixel (x, y) with its coverage; outside RDRAM: black with coverage 7.
Color fetch(const Framebuffer& fb, int x, int y);
// AA (coverage < 7) or dither filter (coverage == 7 and dither_filter), as the hardware's fetch does.
Color fetch_filtered(const Framebuffer& fb, int x, int y, bool dither_filter);
Color divot(Color center, Color left, Color right);
Color lerp(Color a, Color b, unsigned fraction);          // fraction 0..31
Color gamma(Color c, bool gamma, bool gamma_dither, std::uint32_t noise);
```

Comportamiento (de la documentación del hardware; no copiar código):
- `fetch`: 16 bits: canales `(p>>11)&31`, `(p>>6)&31`, `(p>>1)&31` expandidos a 8 bits como `x << 3` (el VI trabaja en 8 bits con los 3 bits bajos en 0); cobertura `((p&1)<<2)|hidden` si `use_coverage`, si no 7. 32 bits: R, G, B bytes; cobertura `(alpha >> 5) & 7` si `use_coverage`.
- Antialias, solo si cobertura < 7: el centro más sus vecinos de cobertura completa entre: fila de arriba x−1 y x+1, misma fila x−2 y x+2, fila de abajo x−1 y x+1. Por canal, `penmin` = segundo menor y `penmax` = segundo mayor de ese conjunto (con 0 o 1 vecinos válidos, ambos = centro). Resultado `((((penmin + penmax − 2c) * (7 − coverage)) + 4) >> 3) + c`, aritmética sin signo de 32 bits, `& 0xFF`.
- Filtro de tramado, solo si cobertura == 7 y está activo: por canal, partiendo del valor de 8 bits del centro, sumar por cada uno de los 8 vecinos (fila de arriba x−1..x+1, fila de abajo x−1..x+1, misma fila x−1 y x+1) +1 si su campo de 5 bits es mayor que los 5 bits altos del centro, −1 si es menor, 0 si igual; resultado `& 0xFF` (sin saturar, como el hardware). En 32 bits los campos de 5 bits son los 5 bits altos de cada byte.
- `divot`: si las tres coberturas son 7, devuelve `center`; si no, por canal la mediana de los tres.
- `lerp`: si `fraction == 0`, `a`; si no, por canal `((((b − a) * fraction + 16) >> 5) + a) & 0xFF` con aritmética entera con signo.
- `gamma`: sin gamma ni tramado, igual; solo tramado: suma a cada canal un bit de `noise` (R bit 0, G bit 1, B bit 2) salvo si vale 255; gamma sin tramado: `2 * isqrt(c << 6)`; gamma con tramado: `2 * isqrt((c << 6) | d)` con d de 6 bits de `noise` (R `noise & 0x3F`, G `(noise >> 6) & 0x3F`, B `((noise >> 9) & 0x38) | (noise & 7)`). `isqrt` entera, resultado truncado a 8 bits.

### Task 3: `Vi::output()` y su paso por Bus/N64

**Files:**
- Modify: `src/core/n64/vi.hpp`, `src/core/n64/vi.cpp`, `src/core/n64/bus.hpp`, `src/core/n64/n64.hpp`
- Test: `tests/n64/test_vi_filter.cpp`

**Interfaces:**
- Consumes: Tarea 2 (`vi::Framebuffer`, `fetch_filtered`, `divot`, `lerp`, `gamma`), Tarea 1 (`Bus::hidden_bits()`).
- Produces: `[[nodiscard]] Vi::Image Vi::output(std::span<const std::uint8_t> rdram, const RdpHiddenBits* hidden) const;`, `[[nodiscard]] Vi::Image Bus::output() const;` (drena el RDP como `image()`), `[[nodiscard]] Vi::Image N64::output() const;`. Imagen siempre 640×480 (NTSC/MPAL) o 640×576 (PAL), ARGB con alfa 0xFF.

Comportamiento:
- Tipo 0/1 o ventana vacía: imagen negra del tamaño completo.
- Ventana: `h_start = (H_VIDEO >> 16) & 0x3FF`, `h_end = H_VIDEO & 0x3FF`, `v_start`, `v_end` de `V_VIDEO`; columna de pantalla `h_start − (PAL ? 128 : 108)`; línea de campo `(v_start − (PAL ? 44 : 34)) / 2`; `hres = h_end − h_start`, `vres = (v_end − v_start) >> 1`. Si la columna inicial es negativa, se recorta y `x_start += x_add * (−columna)`. Todo fuera de la ventana: negro.
- Reescalado: `x_add = X_SCALE & 0xFFF`, `x_start = (X_SCALE >> 16) & 0xFFF`; igual `y_add`/`y_start` con `Y_SCALE`. Línea `y` de la ventana: `curry = y_start + y * y_add`, fila `curry >> 10`, `yfrac = (curry >> 5) & 31`; columna `x`: `xoffs = x_start + x * x_add`, `col = xoffs >> 10`, `xfrac = (xoffs >> 5) & 31`.
- Por píxel: `fetch_filtered` de (col, fila), (col+1, fila), (col, fila+1), (col+1, fila+1); con `DIVOT` (bit 4), cada uno pasa por `divot` con sus vecinos horizontales filtrados; con `AA_MODE != 3` y alguna fracción ≠ 0, `lerp` vertical de ambas columnas con `yfrac` y luego horizontal con `xfrac`; con `AA_MODE == 3`, el de (col, fila). Después `gamma` (bits 3 y 2) con un generador de ruido propio no guardado en estados (xorshift de 32 bits, semilla fija por cuadro: determinista).
- Filas de salida: sin entrelazado (bit 6 en 0) cada línea del campo se escribe en las filas `2y` y `2y+1`; con entrelazado en la fila `2y + campo` (campo = bit 0 de `V_CURRENT`), conservando las filas del otro campo de la salida anterior (búfer `mutable` en `Vi`, no serializado; se descarta si cambia el tamaño o el modo).
- `use_coverage` = `AA_MODE` ≤ 1; `dither_filter` = bit 16.
